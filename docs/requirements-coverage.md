## Status vocabulary

- **Documented**: a requirement exists in a cited source. This makes no implementation claim.
- **Code present / partial**: identified baseline source implements a portion; omitted subfeatures remain open. This is code inspection, not end-to-end verification.
- **Placeholder / planned**: source visibly simulates the outcome, disables it, or a planning document describes it without identified functional wiring.
- **Not established**: this audit lacks sufficient implementation evidence. It does not claim that an exhaustive repository search proves absence.
- **Verified**: a named check actually demonstrated the stated behavior. A successful build verifies compilation/bundling only. No capability group below is certified production-complete.

## First production-workflow acceptance boundaries

These requirements turn the authorized focused workflow into reviewable outcomes. They do not mark the broader groups complete and do not resolve the decisions above by assumption.

1. **Personal workspace:** verified account can create a private case; first-run/demo state is clearly distinct; session change/logout cannot reveal another account's local or remote records. Failed auth and expired sessions preserve the correct owner's pending work. Exercise two separate accounts.
2. **Durable record:** save success means local persistence succeeded. A failure remains visible/recoverable. Entry/attachment IDs, case linkage, raw source, reviewed content and private notes remain distinct. Reload/restart and queue retries cannot duplicate or misassign the record.
3. **Original evidence:** selected/recorded bytes are persisted, retrievable and SHA-256 checked. Main capture can attach real files. Device/capture/receipt metadata is truthful. Originals are never overwritten by previews. Legacy placeholder metadata must not masquerade as recoverable original bytes.
4. **Authenticated recovery and sync:** remote ownership and storage access are tested; new-device recovery retrieves the correct entries and actual original bytes. Offline queues, expired sessions, failed upload and retry state are visible. A staged local implementation is not a verified deployed service.
5. **Useful factual output:** user chooses records/date range, previews, and downloads a readable chronology plus actual selected original evidence with a manifest/source references. Private notes and confidential fields follow the explicit shared-output policy. Missing or mismatched originals are disclosed and cannot be silently reported as included. Do not label this an official court form, legally admissible packet, complete account backup, or all eight reports unless those separate requirements are met.
6. **Verification before beta claim:** exercise new-account setup → capture → attachment → reload → find/review → output, failure/retry paths, second-account isolation and second-device recovery on the chosen release surface. Compilation and UI rendering remain necessary but narrower evidence.
